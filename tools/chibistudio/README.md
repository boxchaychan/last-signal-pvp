# Chibi Live Studio 0.5.2

เครื่องมือทำแอนิเมชัน 2D จากภาพ PNG รองรับจอสัมผัส ตัวอย่างซุสและหุ่นฝึกอยู่ในแอปและเปิดได้ออฟไลน์

## เปิดใช้งาน

- **Android** — เปิดไฟล์ `Chibi_Live_Studio_0.5.2.apk` จากแอปจัดการไฟล์ แอปใช้ Android 8.0 ขึ้นไปและ Android System WebView รุ่นปัจจุบัน APK เซ็นด้วยคีย์ทดสอบสำหรับติดตั้งตรง
- **เบราว์เซอร์** — เปิด `Chibi_Live_Studio_0.5.2.html` ในเบราว์เซอร์ที่รัน JavaScript ได้ ไฟล์มีภาพและโค้ดครบในตัว

## ทำงานกับซุส

1. เปิดแท็บ **คลิป** เลือก **ปาสายฟ้า** กดเล่น หรือแตะ Keyframe เพื่อดูเฟรมง้างที่ 0.44–0.54 วินาทีและเฟรมปล่อยที่ 0.62 วินาที
2. เปิด **แก้ท่าและสลับภาพ** เปิดไกด์กระดูก แล้วลากจุดมือหรือเท้า ใช้ปุ่ม **เพิ่ม / แก้ Key** เพื่อเก็บท่าและภาพสลับ ณ เวลานั้น เลือก Smooth, Linear หรือ Hold ได้ 
3. เปิดแท็บ **Rig** เพื่อขยับตำแหน่งข้อต่อท่าพัก ใช้ Snap เข้ากริด 5 px และเลือกกระดูกแม่ได้ ปิดท่าพักเพื่อจัดท่าคลิปด้วยมือหรือเท้า ปรับสปริงกระดูกผมหรือผ้าได้ในแท็บเดียวกัน
4. เปิดแท็บ **ต่อสู้** กดปาสายฟ้าเพื่อดูการปล่อยเอฟเฟกต์และผลต่อ HP ของเป้าฝึก

## นำเข้าตัวละครใหม่

1. ใน **ส่งออก → โปรเจกต์** เลือก **Rig เปล่า** แล้วนำภาพเข้าที่แท็บ **ชิ้นส่วน** รองรับ PNG ทั้งภาพ, แยกชิ้นจากพื้นโปร่งใส, แยกชิ้นจากพื้นเขียว และลากกรอบตัดเอง
2. เลือกกระดูกสีที่ต้องการผูกกับชิ้นส่วน จากนั้นกด **Snap เข้ากระดูก** หรือลากจุดอ้างอิงของชิ้นเข้าใกล้กระดูกเพื่อ Snap แตะ + หรือ − เพื่อซูม ใช้ **เลื่อน** เพื่อขยับมุมมอง
3. สำหรับภาพต่อเนื่อง ให้เลือก **เมชหลายกระดูก** และปรับด้วย **แปรง Weight** ระบายเพิ่มหรือลดอิทธิพลของกระดูกที่เลือก น้ำหนักของแต่ละจุดถูกปรับให้รวมเป็น 100% และจำกัดที่ 4 กระดูก
4. สำหรับชิ้นที่ทับกัน ให้เลือกชั้นหน้าที่เป็นรอยต่อแล้วกด **รวมกับชั้นล่างและลดรอยต่อ** ระบบเก็บแนวเงารอบนอกและลดเส้นสีเข้มบริเวณขอบที่มีภาพชั้นล่างรองรับ ชั้นต้นฉบับถูกซ่อนไว้และเปิดกลับได้
5. ผูกภาพทางเลือกเข้ากับ Slot มือ สีหน้า หรืออาวุธ แล้วบันทึกตัวเลือกไว้ใน Keyframe ชื่อกระดูกชุดมาตรฐานเหมือนกันระหว่างซุสกับ Rig เปล่า จึงถ่ายโอนคลิปได้
6. ส่งออกคลิปจากแผง **ตั้งค่าคลิปและ Keyframe** แล้วนำเข้าในโปรเจกต์อื่น ระบบจับคู่ด้วยชื่อกระดูกและปรับระยะ X/Y ตามความยาวกระดูกที่ตรงกัน จัดข้อต่อให้ตรงตำแหน่งจริงของตัวละครก่อนใช้คลิปร่วมกัน

## ส่งออก

| ไฟล์ | ใช้สำหรับ |
|---|---|
| PNG | เฟรมปัจจุบัน พื้นหลังโปร่งใส |
| GIF | แสดงคลิปเคลื่อนไหว ใช้พาเลต 256 สีและช่องโปร่งใสหนึ่งระดับ |
| Sprite Sheet | เฟรมสี่เหลี่ยม 256, 384 หรือ 512 px พื้นหลังโปร่งใส เรียงซ้ายไปขวา |
| JSON เฟรม | พิกัดเฟรม เวลา จุดยึด และเหตุการณ์ปล่อยเอฟเฟกต์ จับคู่ชื่อกับ Sprite Sheet |
| JSON โปรเจกต์ | ภาพ โครงกระดูก Weight Slot ฟิสิกส์ และคลิป เปิดกลับมาแก้ต่อได้ |
| JSON คลิป | คีย์เฟรมและความยาวกระดูกสำหรับถ่ายโอนระหว่าง Rig |

Android เปิดหน้าต่างเลือกตำแหน่งจัดเก็บของระบบ เว็บดาวน์โหลดไฟล์ตามปกติ ตัวอย่างซุสใน `examples/` มี 35 เฟรมขนาด 512 × 512 px พร้อม GIF, Sprite Sheet, JSON โปรเจกต์ และ JSON เฟรม 
สำหรับคลิปยาวให้ลด FPS หรือขนาดเฟรมตามข้อความแจ้งเพื่อให้อยู่ในขีดจำกัดขนาดภาพและหน่วยความจำ

## ขอบเขตของรุ่นนี้

- ซุสใช้เมชภาพต่อเนื่องสำหรับ Rig ทั้งตัวและแก้ Weight เริ่มต้นเฉพาะตัว เพื่อรักษาเท็กซ์เจอร์และทรงเส้นขอบเดิม ท่าหมุนตัวและการเดินที่ต้องเห็นด้านข้างต้องเตรียมอาร์ตสำหรับมุมนั้น
- PNG ที่แขนหรือเสื้อผ้าซ้อนกันอยู่ในภาพเดียวแบ่งด้วยกรอบตัดและต้องจัดชิ้นกับ Weight ด้วยมือ ระบบแยกอัตโนมัติหาเกาะพิกเซลที่ไม่ติดกัน และการลดรอยต่อใช้ได้เฉพาะบริเวณที่ภาพซ้อนกัน การวาดพิกเซลส่วนที่ถูกบังต้องทำในอาร์ตต้นฉบับ
- ฟิสิกส์ผ้าและผมใช้สปริงเชิงมุมแบบกำหนดผลซ้ำได้ ยังไม่มีการชนหรือสอดผ่านกันของชิ้นผ้า
- เป้าฝึกจำลองการกระทบและ HP ของการโจมตีของซุส ใช้ตรวจจังหวะของแอนิเมชัน
- ไฟล์ JSON ใช้รูปแบบของ Chibi Live Studio ตัวอย่างสำหรับเกมใช้ Sprite Sheet และข้อมูลเฟรม
- ยังต้องทดสอบประสิทธิภาพบนโทรศัพท์จริงหลายรุ่นและเปรียบเทียบงานภาพด้วยตัวละครอื่นก่อนประเมินว่าถึงเป้าคุณภาพอ้างอิงหรือไม่

## สร้างใหม่และทดสอบ

- `python3 build.py` สร้าง HTML แบบไฟล์เดียวจาก `src/` และ `assets/`
- `android/build.sh` สร้าง APK ด้วย JDK, Android API 35, Build Tools 35.0.0 และคีย์ของผู้สร้าง ตั้งค่า `ANDROID_PLATFORM_JAR`, `ANDROID_BUILD_TOOLS`, `STUDIO_KEYSTORE` และ `STUDIO_KEY_ALIAS`
- ติดตั้ง Playwright และ Chromium แล้วรัน `node qa/browser.cjs chibi_live_studio.html` เพื่อตรวจการใช้งาน กำหนด `CHROMIUM` เพื่อชี้ไปยัง Chromium ที่ติดตั้ง และ `STUDIO_QA_GPU=1` เพื่อทดสอบผ่าน WebGL
- `python3 qa/check_exports.py examples` ตรวจว่า PNG และ GIF เปิดได้จริง พร้อมตรวจว่าเฟรมและพิกัดใน JSON ตรงกับ Sprite Sheet
- `BASELINE_AUDIT.md` สรุปสิ่งที่ทำงานใน ZIP เดิมและส่วนที่เป็นต้นแบบ
